## 90 秒复述

这次做了两件独立的事。第一，页面字体不再走 `next/font` 的 Noto SC Latin 子集——那个文件几乎没有汉字，浏览器会把标题画成缺字。现在 `globals.css` 用 Google Fonts 的完整 SC 样式表，`font-family` 后面还留着本机 `Noto Sans CJK SC` / `Noto Serif CJK SC`，外网挂了也不该再只绑一个 Latin 文件。第二，复述门和黑盒指数的判定被 8 条 Node 测试钉住：空复述、空话「优化了」、不确定函数，都必须不准合；典型 AI PR 必须打到事故预告。验证就是 `npm test`。我没有讲不清的函数。

## 行为变化

开发者和用户打开手册时，中文应能用 Noto / 系统黑体显示，而不是 Latin 子集缺字。合并门槛的判定（不准合 / 事故预告）现在有自动化测试，改 `judgeGate` / `scorePr` 会红。

## 关注点

### 1. 字体从 next/font Latin 子集改成 CSS 栈

- **做什么**：`layout.tsx` 只保留 `Geist_Mono`。Noto Sans/Serif SC 改由 `globals.css` 的 `@import` 拉取，`--font-sans` / `--font-serif` 写成「网络字体 + 系统黑体 + 本机 CJK」。
- **为什么这样改**：`next/font` 对 `Noto_Sans_SC` 只提供 latin 等子集，没有汉字。主字体一旦是这份 Latin 文件，后续 fallback 经常补不回来，Linux 无 CJK 的环境会直接乱码。
- **数据流**：`RootLayout` 渲染 `<html>` → 浏览器解析 `globals.css` → 尝试加载 fonts.googleapis.com → 失败则用栈里的 `Noto Sans CJK SC` / `PingFang SC` / `Microsoft YaHei`。不改路由、不改页面数据、不改 localStorage。
- **失败模式**：
  1. `fonts.googleapis.com` 超时或被拦截：必须还能靠本机 CJK / 系统黑体出字，不能再只挂 Latin。
  2. 旧 HTML/CSS 被缓存：用户仍看缺字，需要硬刷新或清 `next` 缓存后再看。
  3. 本机也没有 CJK 字体：外网再挂，汉字会回落到无衬线默认体，可能再次变差——这是已知残留，不是这次引入的新逻辑。
- **关键符号**：`src/app/layout.tsx:RootLayout`，`src/app/globals.css`

### 2. 用测试锁死复述门和黑盒指数

- **做什么**：新增 `src/lib/logic.test.ts`，`package.json` 增加 `npm test`（`node --experimental-strip-types --test`）。`tsconfig.json` 排除 `*.test.ts`，避免 Next 构建去解析 `.ts` 后缀导入。
- **为什么这样改**：`judgeGate` / `scorePr` 是合并门槛本身。没有测试，下次改文案或阈值会在没人察觉时把「不准合」放宽。
- **数据流**：测试进程直接 import `./gate.ts`、`./score.ts`、`./brief.ts` → 构造表单/输入 → 断言 `status` / `title` / 关键 reason 字符串。不经过 HTTP，不经过 React。
- **失败模式**：
  1. Node 去掉 `--experimental-strip-types`：测试无法加载 TS，CI 会红。
  2. 有人把「优化了…」写长短于 18 字：会先撞「太短」而不是「优化」分支；测试用了足够长的空话，锁的是空话分支。
  3. 把 `*.test.ts` 从 `tsconfig.exclude` 拿掉：`next build` 会因 `allowImportingTsExtensions` 失败。
- **关键符号**：`src/lib/logic.test.ts`，`src/lib/gate.ts:judgeGate`，`src/lib/score.ts:scorePr`

### 3. 复述门页 title 去重

- **做什么**：`/gate` 的 metadata title 从「复述门」改成「当场裁决」，避免模板变成「复述门 — 复述门」。
- **为什么这样改**：标签页标题撞名，定位页失败。
- **数据流**：Next metadata → `<title>当场裁决 — 复述门</title>`。
- **失败模式**：无运行时失败。最大风险是有人按旧标题搜文档。
- **关键符号**：`src/app/gate/page.tsx`

#### 手把手带读

##### `src/app/layout.tsx`：停用 next/font 的 Noto SC

删掉的是：

```ts
const sans = Noto_Sans_SC({
  variable: "--font-sans",
  subsets: ["latin"],
  weight: ["400", "500", "700"],
});
```

以及 serif 的同样写法，还有 `<html className={... ${sans.variable} ${serif.variable} ...}>`。

- **这几行在干什么（删除前）**：让 Next 去拉一份 **Latin 子集** 的 Noto SC，并写成 CSS 变量挂到 `<html>`。汉字几乎不在这个子集里。
- **为什么删**：主字体一旦是这份 Latin 文件，后面 fallback 经常补不回来，页面标题会缺字。
- **删掉会怎样**：不再注入 `--font-sans` / `--font-serif` 这两套 next/font 变量。汉字改由 `globals.css` 的字体栈负责。
- **和前后怎么接**：`Geist_Mono` 仍在，等宽英文不受影响。`RootLayout` 只剩 `dark ${mono.variable}`。

留下的：

```ts
import { Geist_Mono } from "next/font/google";
// ...
<html lang="zh-CN" className={`dark ${mono.variable} h-full`}>
```

- **这几行在干什么**：页面还是中文 `lang`，暗色主题，只挂等宽字体变量。
- **为什么这样写**：mono 仍走 next/font 没问题（它本来就是 Latin）。汉字不该再走同一条错路。
- **改掉会怎样**：若把 Noto 加回来且仍写 `subsets: ["latin"]`，缺字会复发。
- **和前后怎么接**：样式入口仍是 `import "./globals.css"`，真正的中文字体在下一文件。

##### `src/app/globals.css`：字体栈

```css
@import url("https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@400;500;700&family=Noto+Serif+SC:wght@600;700&display=swap");
```

- **这几行在干什么**：让浏览器向 Google Fonts 要**带汉字**的 Noto SC 样式表（按 unicode-range 切），不是 next/font 那份 Latin 文件。
- **为什么写在 CSS 而不是 layout 的 `<head>`**：避免 Next 的 `no-page-custom-font` 警告，全站一份导入。
- **删掉会怎样**：外网字体没了。只要本机还有 `Noto Sans CJK SC` / 苹方 / 微软雅黑，下面的栈还能出字；两层都没有才会缺字。
- **和前后怎么接**：必须排在 `@import "tailwindcss"` 旁边；`--font-sans` 的第一个名字要和这份 family 对上。

```css
--font-sans: "Noto Sans SC", "PingFang SC", "Hiragino Sans GB",
  "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
```

- **这几行在干什么**：浏览器按名单逐个试。先试刚导入的 Noto Sans SC，没有就试系统黑体，再试 Linux 常见的 `Noto Sans CJK SC`。
- **为什么写成一长串而不是只写 Noto Sans SC**：这一长串就是无网/CDN 被墙时的退路。只写一个名字会回到「缺字」事故。
- **改掉会怎样**：删掉 `Noto Sans CJK SC`，Linux 无网容器会再次缺字。
- **和前后怎么接**：`h1` 用 `--font-serif` 的同样策略；`font-family: var(--font-serif)` 不再把 Noto 写第二遍，避免和变量打架。

##### `src/lib/logic.test.ts`：锁死不准合

```ts
import { EMPTY_GATE, judgeGate } from "./gate.ts";
```

- **这几行在干什么**：测试进程直接加载判定函数。扩展名 `.ts` 是给 Node 的 type-stripping 用的，不是给 Next 打包用的。
- **为什么不经过 HTTP**：门槛逻辑与 React 无关，绕开页面能少一层假绿。
- **删掉会怎样**：没有人再锁 `judgeGate` 的分支。
- **和前后怎么接**：所以 `tsconfig.json` 要把 `*.test.ts` 排除，否则 `next build` 会抱怨「不能 import .ts 后缀」。

```ts
behavior: "优化了结算模块让整个流程更干净更好维护",
// ...
assert.ok(verdict.reasons.some((reason) => reason.includes("优化")));
```

- **这几行在干什么**：故意用一句够长的空话。短于 18 字会先撞「太短」，撞不到「优化」分支。
- **为什么要 includes("优化")**：锁的是「空话必须被点名」，不是「任意 reject 就算」。
- **改掉会怎样**：有人把空话检测删了，测试仍可能因为别的字段失败而绿不了，或更糟：空话变短测不到这一支。
- **和前后怎么接**：和 `uncertain: "retry helper 没看懂"` 那条一起，保证「不确定非空」与「空话」是两条独立的不准合。

```json
"exclude": ["node_modules", "**/*.test.ts"]
```

- **这几行在干什么**：Next 的 `tsc` 不再类型检查这份 Node 测试。
- **为什么必须写**：测试为了 Node 而写 `.ts` 后缀；Next 默认禁止这种 import。
- **删掉会怎样**：`npm run build` 红，站点发不出去。
- **和前后怎么接**：`package.json` 的 `test` 脚本仍单独跑这份文件，排除只影响 Next，不影响 `npm test`。

1. **先停**：不要先换回 `next/font`。
2. **纸上状态机**：有网 → 拉 Noto SC → 有字；无网 → 本机 CJK / 系统黑体 → 有字；两层都没有 → 缺字。
3. **第一处分叉**：DevTools 里 `h1` 的 `font-family` 实际命中了哪一个名字。若仍是某份 Latin-only 文件，说明 CSS 没生效或被旧包覆盖。
4. **复现**：
   ```bash
   npm test
   npm run build
   # 浏览器打开 / 和 /gate，看标题汉字，看 title 是否为「当场裁决 — 复述门」
   ```
5. **回滚**：`git revert 2fd4e26`。无数据库、无协议变更。
