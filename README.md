# 复述门

AI 写得动，你讲不清，就不准合。

这是一份针对「AI 实现了功能，开发者没看懂代码」的反黑盒现场手册，不是又一篇正确的废话。三个具体困境对应三套动作：

1. **Diff review 看不出坑** — 先用任务卡把问题定义写死，再用人只审风险、不审美观。
2. **出了问题调试慢** — 先重建状态机，再生成补丁。禁止把 stacktrace 丢给模型当第一反应。
3. **系统变成黑盒** — 用「能讲清楚的人数」管理模块，不用绿条管理知识。

## 本地运行

```bash
npm install
npm run dev
```

打开 [http://127.0.0.1:47291](http://127.0.0.1:47291)。

## 手册里有什么

| 页 | 干什么 |
| --- | --- |
| `/` | 立场、六条不可谈判、明天就能用的最小制度 |
| `/brief` | 生成前的任务卡。五栏没写完就不要开聊 |
| `/gate` | 合并前的复述门。不确定的函数非空 = 不准合 |
| `/score` | 给一份 PR 打黑盒指数。典型 AI PR 默认不及格 |
| `/review` | 人审的八个风险点 |
| `/debug` | 出事时的六步 |
| `/team` | 个人习惯撑不过三个月时的制度 |
| `/lies` | 你正在用来回避理解的八句话 |

任务卡和复述会存在浏览器 `localStorage`，不会上传。
